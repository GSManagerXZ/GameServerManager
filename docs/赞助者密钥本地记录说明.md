# 赞助者密钥本地记录说明

## 1. 背景与变更

设置页面原有的赞助者密钥需要调用第三方接口（`http://api.gsm.xiaozhuhouses.asia:10002/api/key/check`）联网校验，只有校验通过才会写入本地配置，并返回是否过期、到期时间等信息。

本次调整为：**去掉在线校验，改为仅在本地记录**。用户输入密钥后点击「保存密钥」即可完成保存，不再发起任何第三方请求，也不需要等待校验结果。密钥记录后续由其他功能区按需读取调用。

目前已接入的功能区：

- 环境管理 → Java 环境下载（已记录密钥时走赞助者专用通道，详见 [Java赞助版下载链接说明.md](Java赞助版下载链接说明.md)）。
- 游戏部署 → 一键开服（原「在线部署」）：功能对所有人开放，赞助者与非赞助者共用同一下载地址，仅下载请求是否携带赞助者会话 Cookie 不同，详见 [一键开服说明.md](一键开服说明.md)。

## 2. 存储位置与结构

密钥统一保存在服务端 `data/config.json`（开发环境为 `server/data/config.json`）中，通过 `ConfigManager` 读写：

```json
{
  "sponsor": {
    "key": "用户保存的密钥",
    "savedAt": "2026-01-01T00:00:00.000Z"
  }
}
```

- `key`：密钥原文，设置页面会完整回显，便于核对与再次编辑保存。
- `savedAt`：保存时间（服务端写入，无需前端传入）。

兼容说明：旧版本配置中的 `isValid`、`expiryTime`、`validatedAt` 字段不再使用。加载配置时会自动规范化，保留 `key`，`savedAt` 优先取旧 `validatedAt`，缺失时用当前时间补齐。

## 3. 接口

以下接口均挂载在 `/api/sponsor`，且都带有 `authenticateToken` 认证中间件：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/sponsor/save-key` | 保存密钥，请求体 `{ key }`，为空或超过 512 字符返回 400 |
| GET | `/api/sponsor/key-info` | 返回 `{ key, savedAt }`，未保存时 `data` 为 `null` |
| DELETE | `/api/sponsor/clear-key` | 清除本地记录的密钥 |

原 `POST /api/sponsor/validate-key` 接口已移除。前端调用统一走 `client/src/utils/api.ts` 中的 `saveSponsorKey`、`getSponsorKeyInfo`、`clearSponsorKey`。

## 4. 前端表现

设置页面「赞助者密钥」卡片：

- 输入密钥 → 点击「保存密钥」→ 提示「赞助者密钥已记录到本地」，并展示保存时间。
- 已保存时输入框回显完整密钥，可直接修改后再次保存；右侧出现「清除」按钮。
- 已移除「校验中 / 密钥有效 / 密钥已过期 / 到期时间」等校验相关展示。

## 5. 赞助者功能判定入口

由于不再有校验结果，赞助者相关判定统一收口到两个文件，分为「已记录密钥」与「身份已确认」两种语义：

| 入口 | 语义 | 当前返回值 |
| --- | --- | --- |
| `server/src/utils/sponsorStatus.ts` → `getSponsorKey()` | 读取本地记录的密钥（未记录返回 `null`） | 按配置返回 |
| `server/src/utils/sponsorStatus.ts` → `hasSponsorKey()` | 是否已记录密钥 | 按配置返回 |
| `server/src/utils/sponsorStatus.ts` → `isSponsorUnlocked()` | 赞助者身份是否已确认（需要校验结果的功能） | 当前固定 `false` |
| `client/src/utils/sponsor.ts` → `hasSponsorKey()` | 是否已记录密钥 | 按接口返回 |
| `client/src/utils/sponsor.ts` → `isSponsorActive()` | 赞助者身份是否已确认 | 当前固定 `false` |

调用方：

- `server/src/routes/environment.ts`（Java 环境下载通道）使用 `getSponsorKey()`，已记录密钥即尝试赞助者专用通道，失败自动回退普通通道，详见 [Java赞助版下载链接说明.md](Java赞助版下载链接说明.md)。
- `server/src/routes/onlineDeploy.ts`（一键开服下载）使用 `getSponsorKey()`：已记录密钥且下载地址属于赞助者下载服务时，用同一地址 + 会话 Cookie 请求专用节点；会话建立失败或下载失败则去掉 Cookie 重试，功能本身不再鉴权。
- `client/src/components/Layout.tsx`（顶栏赞助者标识）使用 `isSponsorActive()`，仍按「未配置」降级。

`isSponsorUnlocked()` 目前没有调用方，保留作为后续「需要校验结果」的功能的统一判定入口。

后续需要恢复依赖校验的功能时，只需在 `isSponsorUnlocked()` / `isSponsorActive()` 内实现判定逻辑，调用方无需改动。

## 6. 当前功能状态

| 功能 | 现状 |
| --- | --- |
| 设置页密钥保存 | 点击「保存密钥」写入本地配置，完整回显，可再次编辑保存 |
| 环境管理 Java 环境下载 | 未记录密钥走普通通道；已记录密钥走赞助者专用通道（`download-auth/session` 会话 + 同一直链），密钥无效自动回退普通通道 |
| 环境管理 Java 赞助者提示 | 已记录密钥时显示绿色提示「已记录赞助者密钥，Java环境将通过赞助者专用通道下载」 |
| 顶栏「赞助者」标识 | 不显示，等待后续接入 |
| 一键开服（游戏部署页） | 对所有人开放，清单来自云端 JSON；已记录密钥且地址在赞助者下载服务上时走专用节点（同一 URL + 会话 Cookie），否则普通下载 |

网络检测中「GSManager 功能服务」的相关描述已同步为只影响一键开服。
