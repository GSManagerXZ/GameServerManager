# 依赖升级说明

本文档记录本次项目依赖升级的范围、处理原则和验证方式，方便后续继续升级时快速参考。

## 升级范围

- 根目录 `package.json` / `package-lock.json`
- `client/package.json` / `client/package-lock.json`
- `server/package.json` / `server/package-lock.json`

## 处理原则

- 先升级到当前项目可稳定运行的最新兼容版本（semver `^` 范围内的 Wanted 版本）。
- 对于会引入源码破坏性变化的主版本，优先保持在兼容区间内，避免一次性把构建链和业务代码一起推翻。
- 如果某个新版本引入了类型错误或接口变更，先回退到可用版本，再根据需要逐个修复源码。
- 优先修复依赖漏洞，通过 `npm audit fix` 和 `overrides` 字段解决传递依赖的安全问题。

## 本次重点调整

- `client` 的 `react-router-dom` 从 6.30.3 升级到 7.18.2，修复了 3 个 Dependabot 安全警报（#183、#184、#185）。
  - React Router v7 在已启用所有 future flags 的情况下无 breaking changes。
  - 项目已提前启用 `v7_startTransition` 和 `v7_relativeSplatPath` future flags，迁移平滑。
  - `react-router-dom` 包在 v7 中仍作为 `react-router` 的重新导出包发布，导入路径无需修改。
  - 移除了 `BrowserRouter` 的 `future` prop（这些 flags 在 v7 中已成为默认行为）。
- `client` 保持在与现有代码兼容的 React 18、`framer-motion` 11、`lucide-react` 0.x、`vite` 6 组合。
- `server` 保持在与现有代码兼容的 Express 4、`cron-parser` 4、`node-cron` 4、`tar` 7 组合。
- `server` 的 `js-yaml` override 从 `4.2.0` 升级到 `4.3.0`，修复了 `@istanbuljs/load-nyc-config` 传递依赖引入的高危漏洞。
- `client` 的 `postcss` 升级到 `8.5.24`，修复了 Path Traversal 漏洞。
- 根目录和 `server` 的 `tar` 升级到 `7.5.22`，修复了多个 critical 级别的漏洞。
