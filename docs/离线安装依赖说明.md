# 离线安装依赖说明

## 目标

通过 `npm run package:windows`、`npm run package:linux:x64` 或 `npm run package:linux:arm64` 生成的目标平台安装包，在完整解压后不需要执行 `npm install`，也不需要为 PTY、Zip-Tools 或 7z 联网下载二进制。

## 打包行为

打包脚本会在构建阶段完成以下操作：

1. 在安装包的 `server/node_modules` 安装服务端生产依赖。
2. 将目标平台的 Node.js 放入安装包。
3. 优先复用 `server/data/lib` 中已存在的 PTY、Zip-Tools 和 7z 文件；本地没有时仅允许由构建机下载。
4. 使用固定清单校验 PTY 的文件名、大小、SHA-256 和本机能力。
5. 如果任何目标平台运行时二进制最终无法放入 `data/lib`，打包命令会失败，不会输出不完整的安装包。

`server/data/lib` 是构建缓存目录，默认不纳入 Git。需要在完全离线的构建机上打包时，必须预先向其中放入目标平台所需的二进制文件。

## 离线部署

将已生成的目标平台安装包复制到目标机器并解压，然后直接运行包内启动脚本：Windows 使用 `start.bat`，Linux 使用 `./start.sh`。不要在目标机器中运行 `npm install`。

常规在线安装脚本的职责是下载发布归档，因此它本身仍需要网络。离线场景应直接传递已生成的归档，而不是执行 `install-gsm3.sh`。

## 验收检查

解压后应至少存在以下路径：

- `server/node_modules`
- `data/lib/pty_<目标平台和架构>`
- `data/lib/file_zip_<目标平台和架构>`
- `data/lib/7z_<目标平台和架构>`

Windows x64 对应的文件名为 `pty_win32_x64.exe`、`file_zip_win32_x64.exe` 和 `7z_win32_x64.exe`。
