# 内网穿透插件需求说明

## 背景

家用主机、NAS、宿舍网络、运营商 CGNAT 等没有公网入口的环境中，游戏服务端即使启动成功，也不方便让外部玩家连接。

这个问题不是泰拉瑞亚特有的。Minecraft、Palworld、Valheim、Project Zomboid、Factorio 等游戏只要运行在不可直连的网络里，都会遇到类似的端口暴露问题。因此内网穿透能力应当作为跨游戏的可选工具实现，而不是绑定到某一个游戏部署流程。

## 目标

提供一个可选工具，让没有公网 IP 的设备也能把游戏服务端端口暴露给外部玩家。插件只负责网络入口，不改变游戏实例本身的部署、配置和启动逻辑。

## 支持对象

当前按工具职责拆分为两个独立插件：

- `tunnel-helper`：只负责 frp 客户端配置和受管实例，适合已有 frps 服务器的用户。
- `easytier-manager`：负责 EasyTier Profile、受管实例、实时拓扑、路由、运行时动作和 Secure Mode，适合希望多节点虚拟局域网互通的用户。

后续可以扩展到其他工具，但需要满足同一套安全边界：配置可审计、启动命令受控、敏感信息脱敏、进程可停止。

## MVP 能力

- 从实例列表选择一个游戏实例，读取实例名称、工作目录和端口信息。
- frp 支持手动填写本地地址、本地端口、远端端口、远端服务器和认证 token。
- EasyTier 使用类型化 Profile 和规范化 TOML，不再由浏览器拼接启动参数。
- frp 配置保存到 `server/data/tunnels/`；EasyTier Profile、密钥、运行时文件和迁移备份统一保存在 `server/data/easytier/`。
- 通过实例管理创建一个独立的“穿透实例”，让用户用现有实例启停能力管理隧道进程。
- 显示连接说明，例如 frp 的 `远端地址:远端端口` 或 EasyTier 的虚拟 IP、Peer 和路由信息。
- 不要求游戏实例和穿透实例同生命周期绑定，避免穿透失败影响游戏服务本身。

## 已落地能力

### frp：`tunnel-helper`

- `plugin.json` 默认 `enabled: false`，插件界面和客户端 API 只保留 frp 能力。
- 生成 `tunnels/<name>/frpc.toml` 和 `manifest.json`，并创建带可执行文件预检的 `frpc -c frpc.toml` 独立实例。
- 支持配置预览、表单恢复、仅保存配置、保存并创建/更新实例，以及删除配置目录。
- 预览会脱敏展示 `auth.token` 和负载均衡组密钥。
- 可检测、下载和更新 frp；安装结果保存在 `server/data/tools/tunnel-helper/`。
- 支持传输协议、TLS、TCP 多路复用、连接池、代理 URL、日志、UDP 包大小、加密/压缩、带宽限制、Proxy Protocol、负载均衡和健康检查，并保留额外 TOML 入口。
- `server/data/tunnels/` 中的 EasyTier manifest 不会再显示在 frp 配置列表中。

### EasyTier：`easytier-manager`

- `plugin.json` 默认 `enabled: false`，独立版本和独立界面，不再复用 frp 表单或命令生成器。
- Profile 使用 `schemaVersion: 2`；公开 DTO 只返回密钥存在标记，不返回网络密钥、私钥或临时凭据 secret。
- 受管实例只执行 `easytier-core --config-file <profile>/easytier.toml`，浏览器输入不会成为任意 shell 参数。
- 支持 Profile CRUD、启动/停止/重启、能力检测、实时节点/Peer/NAT/路由/流量快照和类型化运行时动作。
- 支持独立 EasyTier Web 生命周期、安装状态和本地配置服务器入口。
- 支持服务端生成并加密保存 X25519 静态身份，以及对等节点公钥固定（peer pinning）。
- 支持实例运行期间签发、列出和吊销一次性临时凭据，并在启动、停止和失败回滚时协调运行时明文凭据文件。
- 支持 ACL 默认允许/默认拒绝策略，以及基于源/目标 CIDR、端口、协议和凭据分组的规则与运行时命中统计。
- 旧 `tunnel-helper` EasyTier manifest 会幂等迁移到 `server/data/easytier/profiles/`；原 manifest 被脱敏并写入迁移标记。
- 迁移前的回滚材料保存在 `server/data/easytier/migration-backups/`：普通 manifest 只保留脱敏副本，恢复所需 secret 使用服务端密钥加密。
- 已迁移 Profile 在 EasyTier 管理控制台中标记“已迁移”，不会再次出现在 frp 插件中。

完整的管理员操作、兼容性要求、Secure Mode、备份恢复和排障说明见 [EasyTier 插件使用说明](./EasyTier插件使用说明.md)。

### 启用和禁用

插件入口已加入侧边栏：

1. 打开“插件”页面。
2. 找到“内网穿透助手 (frp)”或“EasyTier 管理控制台”。
3. 点击卡片上的“启用”或“禁用”按钮。
4. 启用后点击“打开”进入插件界面。

### 已知排查点

- 如果配置文件已经生成但界面没有明显变化，先到“实例管理”检查是否已经创建了 `穿透-<名称>` 实例。
- 如果只想更新已有配置，使用“仅保存配置”；“保存并创建实例”会在存在同名 `穿透-<名称>` 实例时更新该实例。
- “删除配置”只删除 `server/data/tunnels/<名称>` 配置目录，不删除已经创建的穿透实例；实例仍需到“实例管理”中删除。
- 启动 frp 穿透实例前需要先安装客户端；可以点击“下载/更新”，也可以填写 `frpc.exe` 的绝对路径并点击“检测”确认。
- frp 下载/更新完成后，插件会回填可执行文件路径；下次打开插件也会从 `server/data/tools/tunnel-helper/` 恢复已安装路径。已有穿透实例的旧启动命令不会自动变更，需要重新保存配置或删除后重新创建实例。
- Windows 下启动命令应当带 PowerShell 调用运算符，例如 `& 'frpc' -c 'frpc.toml'`；工具缺失时只输出错误，不关闭终端，便于查看失败原因。旧版本插件生成的 `'frpc' -c 'frpc.toml'` 不会执行，需要重新保存并创建/更新实例，或手动修正实例启动命令。
- frp 高级参数不会自动验证 frps 是否支持对应能力；传输协议、UDP 包大小和负载均衡组需要与服务端配置一致。
- 旧 EasyTier 配置只应在“EasyTier 管理控制台”中出现。若迁移失败，检查 Profile 的迁移诊断和 `server/data/easytier/migration-backups/`，不要把备份 secret 复制到浏览器日志或普通工单中。

## 非目标

- 不把 frp 或 EasyTier 变成游戏部署前置依赖。
- 不替用户申请公网服务器或托管中继。
- 不绕过游戏本身的账号、白名单、RCON、反作弊或服务端安全配置。
- 不默认启用通用即插即用协议或自动开放所有端口。
- 不在仓库内提交 frp、EasyTier 等第三方二进制文件。

## 推荐实现方式

### 当前可复用能力

项目已有插件体系和示例插件，可以直接复用：

- 插件目录：`server/data/plugins/`。
- 插件配置：`plugin.json`，支持 `enabled`、`hasWebInterface`、`entryPoint`、`category` 等字段。
- 插件 API 客户端：`gsm3-api.js`，请求前缀为 `/api/plugin-api`。
- 实例 API：`getInstances()`、`createInstance()`、`startInstance()`、`stopInstance()`、`restartInstance()`、`deleteInstance()`。
- 文件 API：`mkdir()`、`writeFile()`、`readFile()`、`exists()`、`listFiles()` 等，可用于写入 `server/data/tunnels/` 下的配置文件。
- 终端 API：可查看终端会话和活跃进程，MVP 阶段只作为状态辅助，不直接拼接任意命令。

### 插件优先

按工具边界拆成 `server/data/plugins/tunnel-helper` 和 `server/data/plugins/easytier-manager` 两个可选插件：

- `plugin.json` 默认 `enabled: false`，避免默认安装后自动出现网络暴露入口。
- `tunnel-helper/index.html` 只做 frp 配置生成、实例创建和状态查看。
- `easytier-manager/index.html` 只通过受认证的 `/api/easytier` 和 Socket.IO 接口管理类型化 Profile 与运行时状态。
- 复用 `gsm3-api.js` 的实例 API、文件 API 和终端/进程列表 API。

这种方式与当前插件体系匹配，风险较低，也不会把第三方网络工具耦合进核心部署页。

### 核心 API 补强

如果后续要做成完整的一键体验，核心需要补一个受限的后台进程/工具管理能力：

- 管理受信任工具定义：工具名称、版本、下载地址、校验和、支持平台。
- 统一保存配置：配置文件、敏感字段、脱敏展示、备份恢复。
- 统一管理进程：启动、停止、重启、日志、健康状态、退出码。
- 限制命令注入：不要让插件拼接任意 shell 字符串后直接执行。
- 与实例端口关联：从游戏配置或实例元数据中读取端口，减少重复输入。

## 安全与维护约束

- 所有后端接口必须加认证中间件。
- 持久化数据放在 `server/data` 下，兼容开发和打包路径。
- token、密钥、服务端地址等敏感字段不要出现在日志和普通列表展示中。
- 下载第三方工具必须记录来源、版本、哈希校验和失败回滚策略。
- Windows、Linux、Docker 三种运行方式的路径、权限和停止信号要分别验证。
- 默认生成的配置应当最小权限暴露，只映射用户明确选择的端口。

## 后续实现计划

1. 让插件从游戏部署清单或实例元数据中自动带出常见端口，减少手动输入。
2. 如需服务端日志脱敏，补核心 API 层的敏感字段处理。
3. 增加镜像源、代理或手动下载 URL，降低 GitHub API 限流和网络不可达对一键下载的影响。

1. 通用内网穿透插件需求说明和界面草图。
2. `tunnel-helper` 插件 MVP：生成配置并创建受管实例。
3. 核心进程/工具 API 补强，完善二进制下载、校验、日志和状态检测。
