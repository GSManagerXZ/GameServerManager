# 登录后认证循环修复说明

## 问题现象

登录成功后，页面请求 `/api/system/info` 返回 401，并提示“认证失败”，随后被重定向回登录页，重复登录流程。

## 原因

应用启动时会先执行 token 验证。旧逻辑无论 token 验证成功还是失败，都会立即预加载系统信息。登录页没有 token 时因此会发出未认证的系统信息请求；如果用户在该请求返回前完成登录，旧请求返回的 401 仍会触发全局认证失效处理，导致刚登录的状态被清除并跳回登录页。

## 修复内容

现在只有 `verifyToken()` 返回认证成功时才预加载系统信息。未登录访问登录页不会再产生这类未认证请求，登录后的系统信息请求会使用刚保存的 `gsm3_token`。

## 验证

在 `client` 目录执行：

```bash
npm run build
```
