# 一键开服说明

## 1. 功能概述

游戏部署页原「在线部署」标签页已更名为「一键开服」：选择云端清单里的游戏 → 填写安装路径 → 面板自动下载服务端压缩包、解压到位，并可一键创建实例。

本次改动的两个要点：

1. **名称变更**：所有界面文案改为「一键开服」。
2. **数据来源变更**：不再请求旧的第三方接口 `http://api.gsm.xiaozhuhouses.asia:10002/api/online-games`，改为实时拉取云端静态 JSON 清单，清单里直接写明下载链接。

功能对所有人开放，**不做准入校验**。赞助者只在**下载环节**享受专用通道，规则与环境管理的 Java 安装完全一致。

> 接口路径（`/api/online-deploy/*`）与 WebSocket 事件名（`online-deploy-log` / `online-deploy-progress` / `online-deploy-complete`）保持不变，避免已有前端构建、插件与脚本失效。代码中的 `onlineDeploy`、`online-deploy` 等标识同理保持不变。

## 2. 云端清单

| 项 | 值 |
| --- | --- |
| 清单地址 | `https://web.files.xiaozhuhouses.asia/files/开源项目/GameServerManager/oneClickDeploy.json` |
| 地址定义 | `server/src/utils/remoteSources.ts` → `ONE_CLICK_DEPLOY_LIST_URL` |
| 仓库内示例 | [oneClickDeploy.json](oneClickDeploy.json)（上传前需替换占位下载地址） |
| 拉取实现 | `server/src/utils/oneClickDeploySource.ts` |

### 拉取与缓存

- 服务端默认使用 **60 秒内存缓存**，命中缓存时不会重复请求云端。
- 前端「刷新列表」按钮会带 `refresh=1` 忽略缓存，直接从云端重新拉取。
- 每次成功拉取后会把清单写入本地缓存文件，路径优先为 `server/data/one-click-deploy/oneClickDeploy.cache.json`（打包后为 `data/one-click-deploy/oneClickDeploy.cache.json`）。
- 云端不可达时自动回退本地缓存，界面会提示「云端暂不可达，当前展示本地缓存清单」；两者都不可用时接口返回 502 并给出中文原因。
- 只有「根节点不是对象」或「缺少 `games` 数组」才判定整份清单失败并回退缓存。

### 容错与空清单

- `games` 为**空数组是合法状态**，表示云端暂未配置游戏：界面显示「云端暂无游戏」，不会弹获取失败。
- 单条记录有问题（缺 `id`、缺 `name`、缺下载地址、格式不支持、`id` 重复）时**只跳过该条**，其它游戏照常加载：
  - 面板会在下载通道卡片下方提示「云端清单有 N 条记录格式无效，已自动忽略」并列出前 5 条原因；
  - 服务端日志会打印每条被跳过记录的中文原因。
- 因此可以先上传一个只有框架、`games` 为空的清单占位，后续再逐条补充游戏。

最小骨架（可直接上传，也可以带一条待补全的模板记录，模板记录会被自动忽略）：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-02-14T10:00:00+08:00",
  "notice": "",
  "games": []
}
```

### 新增或修改游戏

只需要修改云端 JSON，无需发版：

1. 按下方字段规范在 `games` 数组里增删记录；
2. 上传覆盖 `oneClickDeploy.json`；
3. 在面板「游戏部署 → 一键开服」点击「刷新列表」（或等待缓存过期，最多 60 秒）。

## 3. 清单字段规范

### 根节点

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | number | 否 | 清单格式版本，缺省按 `1` 处理 |
| `updatedAt` | string | 否 | 清单更新时间，会展示在面板上 |
| `notice` | string | 否 | 公告文案，非空时展示在一键开服页顶部 |
| `games` | array | 是 | 游戏记录数组，可以为空；不是数组才判定清单非法 |

以下划线开头的字段（如示例里的 `_readme`）会被忽略，可以用作注释。

### 游戏记录

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 唯一标识，重复时后一条会被跳过；建议小写英文 + 连字符 |
| `name` | string | 是 | 显示名称，同时用于生成默认安装路径与实例名 |
| `description` | string | 否 | 卡片描述 |
| `image` | string | 否 | 卡片封面图地址，留空使用内置占位图 |
| `type` | string[] | 否 | 标签，前端按标签提供筛选 |
| `version` | string | 否 | 版本号，展示在卡片上 |
| `supportedPlatforms` | string[] | 否 | `windows` / `linux` / `macos` 的子集（大小写不敏感）；缺省或全部无法识别时按全平台可用处理 |
| `download` | object | 是 | 下载配置，见下 |

### download

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `url` | string | 统一下载地址，**赞助者与非赞助者共用同一个 URL** |
| `fileName` | string | 压缩包文件名；缺省时从下载地址推断 |
| `format` | string | 压缩包格式；缺省时按文件名或地址后缀推断 |
| `size` | number | 压缩包体积（字节），仅用于展示 |
| `platforms` | object | 按平台覆盖上述字段，键为 `windows` / `linux` / `macos`，每个平台条目必须带 `url` |

`url` 必填（顶层与 `platforms` 条目至少要有一处提供）；平台条目只覆盖自己声明的字段，未声明的字段沿用顶层配置。

### 支持的压缩格式

`zip`、`7z`、`tar`、`tar.gz`、`tgz`、`tar.xz`、`txz`。

其中 `zip` / `7z` 走 Zip-Tools（7z 缺少二进制时会按项目既有策略降级），`tar` 系列走 `tar` 库并强制使用 `server/src/utils/tarSecurityFilter.ts` 的路径穿越拦截器，`tar.xz` 先用 7z 解出内层 tar 再按安全规则解压。

## 4. 下载通道规则

**赞助者与非赞助者使用同一条下载链接**，清单里只写一个 `url`。差异只体现在请求本身：本地记录了赞助者密钥、且该地址属于 `download.xiaozhuhouses.asia` 时，面板会先用密钥换取会话 Cookie，再带上 Cookie 请求同一个地址，由下载服务把请求调度到赞助者专用节点。流程与「环境管理 → Java 环境」的通道规则一致：

1. 读取本地记录的赞助者密钥（`ConfigManager` → `sponsor.key`，见 [赞助者密钥本地记录说明.md](赞助者密钥本地记录说明.md)）；
2. 已记录密钥，且 `url` 域名属于赞助者下载服务 → 调 `download-auth/session` 换取会话 Cookie，带 Cookie 请求该地址（赞助者专用节点）；
3. 会话建立失败、或地址是自建直链（域名不属于赞助者下载服务）→ 不带 Cookie，直接普通下载；
4. 带 Cookie 的下载中途失败（如会话失效、链接被拒）→ 清理半成品文件后去掉 Cookie 用同一地址重试一次，日志提示「赞助者通道下载失败，正在改用普通下载重试...」；
5. 两条路径都不校验用户身份，没有密钥的机器照常普通下载。

安全约定：

- 会话 Cookie 只会发送给 `download.xiaozhuhouses.asia` 域名的地址（`isSponsorDownloadUrl()` 判定），不会泄露给自建直链等第三方地址；
- 前端只拿到统一下载地址与 `hasSponsorChannel`（该地址是否支持赞助者专用节点）标记，实际请求由服务端发起。

## 5. 接口

均挂载在 `/api/online-deploy`，都带 `authenticateToken`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/games` | 返回当前平台可用的游戏列表；`?refresh=1` 忽略缓存强制拉取 |
| POST | `/deploy` | 请求体 `{ gameId, installPath, socketId }`，立即返回 `deploymentId`，实际过程通过 WebSocket 推送 |
| POST | `/cancel/:deploymentId` | 取消进行中的开服任务，会中断下载并清理临时压缩包 |
| GET | `/deployments` | 返回进行中的开服任务 |
| POST | `/refresh` | 强制重新拉取云端清单，返回游戏总数与来源 |

`GET /games` 响应中的 `meta` 字段：

| 字段 | 说明 |
| --- | --- |
| `updatedAt` / `fetchedAt` | 清单声明的更新时间 / 本次数据获取时间 |
| `origin` | `remote` / `memory-cache` / `disk-cache` |
| `empty` | 清单已拉到但当前平台没有可用游戏 |
| `totalGames` | 清单里的游戏总数（未按平台过滤），用于区分「云端没配置」与「当前平台不支持」 |
| `invalidGames` | 被跳过的无效记录（含位置与中文原因），前端据此提示清单作者 |
| `notice` | 公告文案 |
| `platform` | 当前平台键 |
| `sponsorChannelAvailable` | 本地是否已记录赞助者密钥 |
| `sponsorChannelGames` | 当前平台可用游戏里下载地址支持赞助者专用节点的数量 |

> 本次同时修正了取消接口的路径：前端原先请求 `POST /api/online-deploy/cancel`（缺少 `deploymentId` 路径参数）会 404，现已改为 `POST /api/online-deploy/cancel/{deploymentId}`。

## 6. 前端表现

- 标签页名称：**一键开服**。
- 顶部卡片展示下载通道状态：已记录密钥时提示赞助者专用节点已启用及支持的游戏数量，未记录时提示前往设置页保存密钥；同时展示云端清单更新时间，回退本地缓存时会标注。
- 卡片会展示版本、体积，以及该游戏地址是否支持赞助者专用节点（统一走同一链接，非赞助者同样可用）。
- 开服进度通过 WebSocket 实时刷新（百分比 + 中文步骤 + 日志），完成后可直接「创建到实例」。
- 失败事件现在会正确显示为失败（此前失败事件缺少 `result` 字段，界面会误判为成功）。
