# 实例启动、停止与 Steam 安装终端说明

## 实例启动

点击实例的“启动”后，服务端会先创建并确认 PTY 控制通道，再返回终端会话 ID。终端页面可在会话就绪后立即打开，启动命令仍由实例配置执行。

若实例配置了 Java 环境（`javaVersion`，例如“Java服务端/我的世界Java版”或带 Java 环境的一键开服实例），服务端会在执行启动命令前先向终端写入一行环境变量设置命令（`JAVA_HOME`、`PATH`），使启动脚本 `run.sh` / `run.bat` 等内部的 `java` 也使用所选版本，详见 [实例 Java 环境注入说明](./实例Java环境注入说明.md)。

## 启动命令的当前目录前缀

终端不会把「工作目录」当作命令搜索路径，裸写工作目录里的脚本名都会启动失败：

- Windows 终端是 `powershell.exe`（不像 `cmd.exe` 会从当前目录解析），执行 `start.bat` 会报
  `The term 'start.bat' is not recognized ...`，必须写成 `.\start.bat`；
- Linux/Mac 终端是 `bash`，执行 `start.sh` 会报 `command not found`，必须写成 `./start.sh`。

服务端在启动时做了两层处理：

- “Java服务端/我的世界Java版”自动检测到启动脚本时，Windows 下生成 `.\start.bat` / `.\run.bat`，
  Linux/Mac 下生成 `./start.sh` / `./run.sh`；
- 其它类型（含用户手写启动命令）如果首个词是**不带路径的本地脚本/程序名**
  （Windows：`.bat`、`.cmd`、`.ps1`、`.exe`、`.com`；Linux/Mac：`.sh`），
  且该文件确实存在于工作目录，服务端会在本次启动时自动补上 `.\` 或 `./` 前缀，并在日志中打印补全前后的命令
  （Linux/Mac 下补上 `./` 后同时会走已有的 `chmod +x` 逻辑）。

补全只作用于本次执行的命令，不会改写实例配置里保存的启动命令；已经带 `.\`、`./`、相对路径或绝对路径的命令保持原样，
`java -jar ...`、`bash run.sh` 这类由 PATH 解析或被解释器执行的命令也不受影响。

## 实例停止

点击“停止”后，接口立即返回“停止命令已发送”，实例状态会先显示为“停止中”。服务端在后台等待停止命令生效；若进程未在优雅停止期限内退出，会自动执行有界的强制关闭。终端退出后实例状态会自动更新为“已停止”。

## Steam 游戏安装

Steam 安装使用普通面板终端会话，并通过终端输入 SteamCMD 命令。实际安装命令引用服务端生成的一次性脚本，账户密码不会写入命令行；SteamCMD 完成后外层终端自动退出，面板据此提交实例配置并清理临时脚本。
